# 小说、题材与大纲

## 输入与需求理解

灵感或原文、主题、类型偏好、篇幅和允许改编范围。

## 分析方法

建立主角目标、障碍、代价、成长与关系；比较线性、悬念和群像结构，规划伏笔和兑现。

## 方案应包含什么

故事概念、人物关系、世界规则、事件骨架、分章/分集思路、主题表达与结构选择理由。

## 什么情况下应提出异议

事件只靠巧合解决；人物目标不清；每集重复同一冲突；混合类型缺乏主次。

## 用户指定进入制作后

按指定范围写书名简介、大纲、细纲或正文；原文事实与新增创作明确区分。

## 验证要点

主要选择有后果、伏笔有兑现、阶段人物变化有行为证据，信息顺序自洽。

### 具体交付和上下游

- **交付**：咨询交付选题/结构建议；授权后交指定大纲、细纲或完整正文，以及对应原句/章节覆盖和续写断点。
- **上游**：继承strategy已选方向、原文版本、人物/世界事实、允许新增范围、已写章节和最后有效状态。
- **下游**：给screenplay或storyboard传当前有效原稿、章/段/句编号、原句锁、人物关系、知识揭示、道具归属及下一未覆盖句；原著续写与影视改编的新增分别登记。
- **持续依据**：依技能 `references/project_state.md` 保存当前有效成果版本、覆盖/下一单元、已确认与设计/待定分别记录、进入/退出状态及改动传播。项目目录沿用用户位置，作品不写回公共语言库；单次咨询不强建空项目。
- **继续与修改**：继续读取当前授权范围和对应故事线最近有效末态，缺后文不编原著续篇；修改先重出完整受影响单元，再同步必须传播的资产、知识、声轨与时间线，已完成无影响部分保留。
- **检查口径**：来源/参数/文本自审与实际生成结果分别标注，未访问、未生成、未试听不写成已验证。
