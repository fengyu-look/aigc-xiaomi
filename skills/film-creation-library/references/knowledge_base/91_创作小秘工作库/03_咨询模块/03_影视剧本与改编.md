# 影视剧本与改编

## 输入与需求理解

原文或梗概、忠实度、不可改事实、目标时长与剧本用途。

## 分析方法

拆事实和心理信息，寻找人物行动、场景目标、阻碍和转折；比较旁白、表演外化与场景重构。

## 方案应包含什么

改编边界、剧情覆盖关系、场次安排、人物行动、对白策略、必要新增及其理由。

## 什么情况下应提出异议

旁白重复画面；新增冲突改变锁定事实；为影视感降低人物智商；对白时间不足。

## 用户指定进入制作后

输出用户指定场次或全文，保留原句与覆盖要求；导演物理细节按用途展开。

## 验证要点

原文覆盖、台词准确、因果清楚、每场有状态变化，新增部分可追溯。

### 具体交付和上下游

- **交付**：咨询交付改编边界和场次安排；授权后交完整指定剧本、原句覆盖、必要制作卡及改动传播清单。
- **上游**：接原文版本/P-S节点、事实与真假两维、已授权改编权限、角色阶段、场景地图、道具/关系/知识末态。
- **下游**：给images传C/SC/P实体与资产职责；给storyboard传SC/B/D/V编号、逐字对白、动作起终和声源。旁白让观众知道的内容不自动成为场内角色知识；修改后同步受影响场次。
- **持续依据**：依技能 `references/project_state.md` 保存当前有效成果版本、覆盖/下一单元、已确认与设计/待定分别记录、进入/退出状态及改动传播。项目目录沿用用户位置，作品不写回公共语言库；单次咨询不强建空项目。
- **继续与修改**：继续读取当前授权范围和对应故事线最近有效末态，缺后文不编原著续篇；修改先重出完整受影响单元，再同步必须传播的资产、知识、声轨与时间线，已完成无影响部分保留。
- **检查口径**：来源/参数/文本自审与实际生成结果分别标注，未访问、未生成、未试听不写成已验证。
